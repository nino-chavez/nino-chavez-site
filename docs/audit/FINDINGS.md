## Correction to Phase 1

My Phase 1 pass recorded "URL-backed filters — conforms at the server," reasoning
that `/work?domain=commerce` rendering 206 tags against 596 unfiltered proved the
filter was applied server-side.

**That was wrong.** 206 tags is the *empty* state. The filter was rejected, not
applied. Two reviewers caught it independently. The corrected finding is F1 below,
and it is the most serious defect in the audit.

The lesson generalizes: a smaller render is not evidence of a working filter. The
check has to count records, not bytes.

## S1 — blocks launch

### F1. Filter URLs are case-sensitive, and the IA contract's own examples return nothing `[verified]`

The three collections use different casing conventions, and neither normalizes
input. A visitor who shares, edits, or hand-types a filter URL gets a silent
empty page with no error and no correction.

| URL | Records returned |
|---|---|
| `/work` | 32 |
| `/work?domain=Commerce` | 4 |
| `/work?domain=commerce` | **0** |
| `/work?state=live` | 7 |
| `/work?state=Live` | **0** |
| `/blog?type=Essay` | renders 2,685 tags |
| `/blog?type=essay` | **269 tags — empty** |

`domain` is capitalized in the registry (`Commerce`, `Local-first`, `Media &
assets`). `state` is lowercase (`live`, `internal`). Blog `type` is capitalized.
So the same site teaches two opposite conventions.

Worse: `IA-NAVIGATION.md` lines 267–271 document five example URLs as the
contract's own illustration of URL-backed filtering. Three of the five return
zero results against this build:

- `/work?domain=volleyball` → registry holds `Volleyball` → **0**
- `/work?domain=practice&state=source` → registry holds `Practice` → **0**
- `/work?state=internal` → works, by coincidence of casing

**Blast radius — the in-page controls are fine.** The `<option>` values emitted
by `/work` carry the registry's own casing (`Commerce`, `Local-first`, `Media &
assets`, and lowercase `building` / `internal` / `live` / `paused` / `source`).
So clicking a filter works. What breaks is every URL that arrives from outside
the control: shared, bookmarked, hand-edited, or copied from the IA contract.
That keeps this at S1 — sharing a filtered view is a named capability — but the
fix is normalize-on-read, not a change to the option values.

**The site already knows how to do this.** `/search?q=rally` and `/search?q=Rally`
both return the same single result. Search normalizes case; the three collections
do not.

**Correction to an earlier draft of this finding.** I first wrote that a rejected
filter renders no empty state. That is wrong for `/work` — it does render "No work
matches the current view," which the existing suite already asserts. Measured
properly, by counting distinct record links on the full document rather than
inferring from page size:

| URL | Records | Empty-state message |
|---|---|---|
| `/work` | 32 | — |
| `/work?domain=Commerce` | 4 | — |
| `/work?domain=commerce` | **0** | **yes** |
| `/demos` | 20 | — |
| `/demos?type=technique` | 9 | — |
| `/demos?type=Technique` | **empty** | **no** |
| `/demos?q=zzznothing` | **empty** | **no** |
| `/blog?type=Essay` | 2,685 tags | — |
| `/blog?type=essay` | **269 tags — empty** | **no** |

So the missing empty state is a real defect, but it belongs to `/demos` and
`/blog`, not `/work`. `/work` handles the rejection honestly; the other two go
blank with nothing said.

The method note matters more than the correction: three of my inference errors in
this audit came from reading page size or a truncated grep as evidence of
content. Counting the records is the only check that answers the question.

- **Contract**: `IA-NAVIGATION.md` §Discovery — URL-backed search and filtering;
  the documented examples are part of the approved contract.
- **Repro**: `curl -sS 'http://localhost:3000/work?domain=commerce' | grep -o 'href="/work/[a-z0-9-]*"' | sort -u | wc -l` → 0
- **Fix**: normalize case on read for every facet, and give the collections the
  same explicit empty state `/search` already has.

### F2. `/about` — five practice actions are clipped to an 18px column at 390 `[verified]`

OPEN THE WORK, SEE VOLLEYBALL WORK, OPEN PHOTOGRAPHY, READ SIGNAL DISPATCH, and
LISTEN ON SOUNDCLOUD render inside a three-column grid whose third track is a
fixed 18px. The links carry `overflow: hidden; white-space: nowrap`, so on a
phone the text is in the DOM, invisible on screen, and 18×17px as a target.

**It is not a mobile-only defect.** The containment reviewer found the collapse
is driven by `max-width: 760px` on `/about` and `720px` on `/links` — and a 1280
desktop at 200% zoom has a 640px CSS viewport, so both fire there. Verified
directly: at a 640 viewport the same links still measure 18×17. That makes this a
reflow failure on desktop, not just a phone problem.

- **Contract**: `PRODUCT.md` §Success criteria — "at least one real object can be
  acted on immediately." WCAG 2.2 AA 2.5.8 (24×24 minimum) and **1.4.4 Resize
  Text / 1.4.10 Reflow** at 200% zoom.
- **Evidence**: `evidence/d0cfd0e/shots/DIAG-about-390-links.png`; measured
  `grid-template-columns: 30px 259px 18px`, link box 18×16.84 at both 390 and
  640. Same links measure 105×17 and 147×17 at 1280 unzoomed.
- **Root cause** (`roles/containment.md` RC2): three rules deliberately put an
  element into an 18px track with `overflow: hidden; white-space: nowrap; width:
  18px; color: transparent` and restore an arrow through a pseudo-element. That
  is intentional where the collapsed thing is a *label*. On `/about` the
  collapsed element is the anchor itself.
- **Fix**: wrap the action below the description at small widths rather than
  holding a third grid track. `/links` needs the same fix (C5).

### F3. Every detail route carries the homepage's title `[verified]`

Eight routes return `<title>Nino Chavez — Open Practice</title>` — the homepage
title. All four `/work/:slug`, both `/demos/:slug`, and both
`/demos/applied/:slug`. The static routes and `/learn/:track` all set their own
title correctly, so this is scoped to detail pages that never call
`generateMetadata`.

The cost is concrete: browser tabs, history, bookmarks, and screen-reader page
announcements cannot distinguish one project record from another.

- **Contract**: WCAG 2.2 2.4.2 Page Titled — **Level A**.
- **Repro**: `grep -o '<title>[^<]*</title>' evidence/d0cfd0e/html/work_rally-hq.html`
- **Fix**: add `generateMetadata` to the three detail route files.

### F4. `/demos` says "Watch session"; the destination has no player and no link to one `[resolved]`

**Resolved by the native-story migration.** The collection now says "Open full
demo." Every session route renders the complete source story as native HTML
inside the consolidated site, including its chapters, diagrams, evidence,
images, and original visual system. The old Demos origin is no longer the

The remainder of this entry records the defect at the audited revision.

`/demos` labels sessions "Watch session" and "Watch the session." The session

So the collection's headline verb resolves to a page where nothing can be

`/demos/browse-tool`, two social links, a mailto, and the broken image URL.

That makes the fix small: render the `href` the generator already supplies.

- **Contract**: `PRODUCT.md` §Content model — every work object has "an honest

- **Evidence**: full `href` set extracted from the rendered document with no

### F4a. The Demos collection renders broken images from a stale remote index `[resolved]`

**Resolved by republishing the content source and migrating the stories.**
`nc-demos.pages.dev` now publishes the current index, story JSON, and assets.
The consolidated site revalidates that feed and carries a validated bundled
fallback. The retired Demos subdomain is no longer used as an image origin.
Applied-technique cards remain typographic by design, but every technique opens

hotlink a 403 origin. The real shape is more specific, and more fixable.

falls back to the bundled `app/demo-data.json` when that fetch fails. The bundled
file is already correct — 12 of 12 sessions carry a local `artifact.src` such as
`/work/demo-twelve-messages.jpg`. The remote index still carries
`https://demos.ninochavez.co/…/img/*.jpg`, and that origin returns **403**,
including at its root.

So the corrected data is committed and dead. The site serves the stale remote.

Split by record type:

| Records | What renders |
|---|---|
| 12 sessions | a cross-origin image from a 403 origin — broken |
| 8 applied techniques | **no image at all** — 0 of 8 carry an `artifact` |

Not inferred from a status code: the Phase 1 capture, in a real headless Chrome,
shows `/demos/twelve-messages` rendering the broken-image glyph and its alt text
— "Published Instagram story rendered by the demo's pipeline" — inside the dark
media field where the evidence should be.

The README calls this collection "a major proof surface." Half of it shows a
broken image and half shows nothing.

- **Contract**: `OPEN-PRACTICE-ART-DIRECTION.md` §Creative thesis — artifacts
  appear "in forms appropriate to the work"; `PRODUCT.md` §Success criteria —
  "real screenshots and photographs carry more visual weight than decorative
  typography."
- **Evidence**: `shots/demos_twelve_messages-1280-fold.png`; rendered `img src`
  on `/demos/twelve-messages` and `/demos/browse-tool`;
  `curl -o /dev/null -w '%{http_code}' https://demos.ninochavez.co/` → 403;
  `app/demo-data.json` sessions with a non-local `artifact.src`: 0 of 12.
- **Resolution**: the publisher moved to a working Pages origin; the app rejects

## S2 — contract clause violated

### F5. `/learn/:track` — three track titles overflow the viewport at 390 — **fixed in the working tree** `[verified]`

At `d0cfd0e`, `ENTERPRISE` renders 415.75px wide in a 375px body; the page
scrolls sideways by 59px and the final `E` is cut. The containment reviewer
computed from Anton's own advance-width table that `STRATEGIST` and `ARCHITECT`
fail by the same mechanism and were simply never captured, and that `EXPLORER`
escapes its column while clearing the viewport by under 4px. The rule breaks at
roughly **eight characters**. Its prediction for `ENTERPRISE` was 413.9px against
a measured 415.75 — 0.45% error, so treat the other three as sound.

`/learn/:track` is the only display title on the site whose text comes from data
rather than from a word a designer sized against once.

**Already fixed.** The working tree changes the rule from
`clamp(4.8rem, 24vw, 8.5rem)` to `clamp(3.55rem, 18vw, 8.5rem)` and moves a
breakpoint from 900 to 940. I rebuilt with it and measured all seven tracks: at
both 390 and 640 (a 1280 desktop at 200% zoom), every title is contained in its
column and no document overflows. That edit is not mine — see *Subject drift*
below.

- **Contract**: `OPEN-PRACTICE-ART-DIRECTION.md` §Typography — "Display type must
  remain inside its owning field at every supported width."
- **Evidence**: `shots/DIAG-learn-enterprise-390.png`; `scrollWidth 434 > 375` at
  `d0cfd0e`. Post-fix measurement: text 354 / box 354 at 390, 604 / 604 at 640.
- **Remaining work**: the fix resizes the type; it does not make the rule
  self-enforcing. A future track name longer than `ENTERPRISE` reopens it. The
  durable fix is sizing against the container. Worth a regression case either way.
